### CanopyCover reverse-causation check — baseline-only (Set1) comparison, added 2026-08-13, numbers corrected 2026-08-15

**Context**: the project's own data cheat-sheet (`documentation/data_exploration_gpkg/Forest LiDAR
& Inventory – Key Terms Cheat Sheet.md`, §3.2/§3.4/§13) flags `CanopyCover` as a "downstream
consequence of the growth process," not a genuine driver — confirmed it and `elev_percentile_95th`
come from the SAME LiDAR CSV/ALS flight (not independent surveys), and correlations with all 3
targets are moderate (Pearson 0.35-0.47), ruling out literal duplication (`GapFraction`, an exact
1-CanopyCover duplicate, correlates far higher) but not resolving the causal-direction question.
This is NOT the same category as the `Age` circularity bug (Age is algebraically inside the CR
formula; CanopyCover is not in any of the 3 target formulas) — a judgment call, not a proven leak.

**Test run**: `nested_set1_baseline` (the 4 stand-structure columns alone — `CanopyCover`,
`time_since_thinning`, `time_since_thinning_missing`, `recent_thinning_5yr`) had never actually
been fit for RQ2 before (only Set2/3/4, which already include baseline + environmental candidates
together). Widened `--set-name` choices in `run_rq2_attribution.py`/`evaluate_rq2_attribution.py`
(additive, no behavior change for existing sets) and ran all 5 folds locally.

**Result — see the corrected Set1 row in the main results table above.** Two findings:
1. Baseline alone reaches only R2=0.21-0.22 (EN/XGBoost, now essentially identical to each other
   post-correction) — environmental variables add a real, non-trivial +0.14-0.19 R2 on top for
   XGBoost (0.222→0.375-0.416, an even bigger jump than the pre-correction read since the
   full-set XGBoost numbers rose too) — baseline is nowhere close to "the whole model."
2. NLME's variance-explained metric (specifically BETWEEN-COMPARTMENT/spatial variance, not
   overall row-level variance) is ~0 for baseline alone (0.016±0.078, one fold negative) vs.
   0.05-0.20 for the full sets — baseline has real row-level predictive power but explains almost
   none of the spatial pattern, while environmental variables explain a real share of it. (NLME
   was never affected by the XGBoost fix, this finding is unchanged.)

**Conclusion**: supports treating `CanopyCover`/thinning explicitly as baseline stand-structure
CONTROLS in the write-up (expected to dominate row-level R2, not itself the interesting
attribution finding), with the environmental variables' contribution beyond that baseline as the
actual headline — a defensible, evidence-backed reframe rather than "CanopyCover just happens to
win." This finding is unaffected by, and actually slightly strengthened by, the XGBoost
hyperparameter correction.

### Moran's I on the EN/XGBoost residual — run 2026-08-15, a substantial finding

**What this answers**: after NLME/EN/XGBoost use environmental variables to explain
`mean_cr_residual`, does what's left over (the model's own residual) still cluster spatially? Used
`compute_residual_morans_i()` (`models/growth_curve_attribution/residual_spatial_autocorrelation_check.py`,
unchanged, k=8 nearest-neighbour weights matching this project's own established LISA/RQ3
convention, 999 permutations), pooled predictions across all 5 folds, `x`/`y` joined in via
`load_plot_coordinates()` (one join, RQ2b's `predictions.csv` doesn't carry coordinates natively).

| Set | EN residual Moran's I | EN p | XGB residual Moran's I | XGB p |
|---|---:|---:|---:|---:|
| Set1 (baseline-only) | 0.738 | 0.001 | 0.735 | 0.001 |
| Set2 | 0.690 | 0.001 | 0.655 | 0.001 |
| Set3 | 0.700 | 0.001 | 0.673 | 0.001 |
| Set4 | 0.693 | 0.001 | 0.659 | 0.001 |

**Substantial, significant spatial clustering remains in every case, and more environmental
information barely moves it.** Moran's I stays in the 0.65-0.74 range regardless of set (baseline-
only vs. the full environmental set), with p at the permutation floor (0.001, the smallest value
999 permutations can report) every time. Going from Set1 (4 baseline columns) to Set4 (19 columns,
every category, VIF-screened) only nudges EN's Moran's I from 0.738 to 0.693 — a small reduction,
not a resolution. XGBoost shows the same pattern, slightly lower magnitude throughout.

**Why this matters beyond RQ2b itself**: this is real, current-tier evidence that RQ2b's global
attribution models leave a large amount of spatially-structured signal unexplained, and that
*more* environmental data (within the current candidate pool) does not meaningfully close that
gap. That's a concrete, evidenced motivation for RQ3's spatially-varying (GNNWR) approach — not
"a fancier model tried for its own sake," but a response to a demonstrated gap that adding more
global environmental features does not fix. For comparison, the old-tier (pre-VIF, pre-restructure)
RQ3 check found EN/XGBoost residual Moran's I of 0.709/0.708 on the `terrain_wind_plus_management`
scope — this current-tier RQ2b result (0.65-0.74) sits in the same range, suggesting this is a
persistent characteristic of this dataset/target family, not an artifact of the old tier or a set
choice.

### CanopyCover-dropped ablation (2026-08-16) — the decisive test for the reverse-causation concern

**What this evaluates**: the SHAP-dominance framing above ("modest, 1.2-1.7x margin over the #2
variable") describes CanopyCover's RELATIVE rank margin while it's still in the model — it does not
directly show how much unique predictive power CanopyCover itself contributes, or whether removing
it lets `dist_to_road` (the #2 variable) simply absorb the same signal. This ablation tests both
directly.

**How**: refit Elastic Net + XGBoost on Set4 with `CanopyCover` removed (18 of the 19 columns),
same split (`spatial_kfold_split`, seed 42, 5 folds), same fixed XGBoost config
(`n_estimators=500, max_depth=4, learning_rate=0.04`, early stopping against the same val split),
same missing-row handling as the production pipeline (`drop_rows_with_missing_features`) — reuses
`run_rq2_attribution.py`'s exact fit logic via its own imported functions, not a reimplementation.
SHAP recomputed the same way as the existing check (`compute_rq2_shap.py`'s own method,
`shap.TreeExplainer`, mean |SHAP| pooled across folds weighted by fold test size). No new script
saved to `models/` — one-off, see this note for the method.

| | R2 (mean of per-fold), WITH CanopyCover | R2, WITHOUT CanopyCover | Drop |
|---|---:|---:|---:|
| Elastic Net | 0.350±0.040 | 0.231±0.062 | -0.119 (34% relative) |
| XGBoost | 0.388±0.057 | 0.249±0.076 | -0.139 (36% relative) |

**Mean \|SHAP\|, without CanopyCover, top 4**: `dist_to_road` 0.869, `chelsa_bio12_precip_mm`
0.829, `slope_degrees` 0.677, `whcl` 0.373. Compare to WITH CanopyCover: `CanopyCover` 1.430,
`dist_to_road` 1.003, `chelsa_bio12_precip_mm` 0.843, `slope_degrees` 0.601.

**This sharpens the reverse-causation concern rather than resolving it, in a specific and honest
way — two findings pulling in different directions**:
1. **The R2 drop is large, not modest** — removing CanopyCover costs roughly a third of both
   models' explanatory power. This is a bigger effect than the earlier "1.2-1.7x SHAP margin"
   framing implied; CanopyCover carries substantial, not-easily-replaceable predictive signal that
   nothing else in the set backfills.
2. **But `dist_to_road`'s own SHAP magnitude does NOT rise to compensate** (1.003 -> 0.869, actually
   slightly lower) once CanopyCover is removed. If CanopyCover were simply "stealing" correlated
   credit that rightfully belonged to `dist_to_road`, removing it should have let `dist_to_road`'s
   importance rise to fill the gap — it didn't. This specific mechanism (correlation-driven credit
   theft from the #2 variable) is not what's happening.

**Honest conclusion**: CanopyCover carries real, large, non-redundant signal — but this ablation
cannot distinguish whether that signal is "CanopyCover is a genuine driver" or "CanopyCover is
entangled with the same growth process that produces the residual target, and no other single
variable happens to capture the same entanglement." The write-up position established earlier
(present CanopyCover/thinning explicitly as baseline stand-structure controls, not the interesting
attribution finding itself) remains the defensible one — if anything, this result is a reason to
lean on that framing more explicitly, not less, given how much of the model's power turns out to
run through this one variable.
