**Set4 x 6survey FAILED, then fixed same day** (`KeyError: Requested dummy columns not found
after encoding: ['ceh_pedotope=2.0', 'ceh_pedotope=8.0', 'ceh_textural_composition=2.0']` — these
rare soil categories are present in 4survey's larger population but entirely absent from
6survey's ~7,467 plots, so `pd.get_dummies()` never creates those columns for 6survey). Decision
taken: zero-fill the missing dummy columns rather than skip the combination — a dummy column
absent from a cohort's population is real information ("0% prevalence"), not missing data, and
zero-filling is mathematically inert for both models while keeping Set4's column count identical
across cohorts for a fair comparison. Implemented as a new shared helper,
`add_missing_dummy_columns_as_zero()` (`broad_environmental_check.py`), used by both
`run_columns()` (this note) and GNNWR's `build_table_from_columns()` (same bug will otherwise hit
GNNWR's own Set4x6survey runs). Re-ran the exact failing combination locally afterward to
confirm — result now included below.

### How these numbers were generated

- `models/growth_curve_attribution/run_rq3_en_xgb.py` → `broad_environmental_check.run_columns()`
  → `spatial_cv_check.run_spatial_cv()` (5-fold spatial CV, pooled predictions across all folds
  give the pooled R2; per-fold R2 computed separately for the fold-SD column).
  `collect_fold_models=True` (added 2026-08-10) additionally returns each fold's fitted EN/
  XGBoost model, used below for the coefficient/importance tables — this is the fix that made
  per-fold attribution possible at all for RQ3 (previously `run_spatial_cv()` discarded fitted
  models after each fold, see the earlier session note on this).
- Elastic Net coefficients: `elastic_net_coefficients_by_fold.csv`, mean ± SD across the 5 folds.
- XGBoost gain importance: `xgboost_gain_importance_by_fold.csv` (built-in `feature_importances_`,
  free byproduct of fitting, no extra pass over the data), mean ± SD across 5 folds.
- 4survey only shown for the coefficient/importance tables (6survey's smaller population makes
  per-fold coefficient estimates too noisy to be worth reporting yet — see the R2 table below for
  just how much noisier 6survey's fold-to-fold R2 already is).

**Same `CanopyCover` dominance as RQ2b** — by a wider margin here (EN coefficient 2–3x the next
largest variable; XGBoost gain 0.26–0.34, roughly 3x the next-largest) — the single most
consistent finding across RQ2b and RQ3 alike. **The 3 rare-soil-dummy columns in Set4

XGBoost** (gain importance 0.000–0.007, the three lowest of all 20 Set4 columns) — consistent
with them being rare-category, low-signal additions, separate from the reason 6survey can't use
them at all (population absence, not weak signal).

**Set3's Elastic Net coefficients for `time_since_thinning`/`time_since_thinning_missing` are
essentially pure noise** (SD exceeds or vastly exceeds the mean) — flag before citing Set3's EN
coefficients for those two variables specifically; every other Set3/Set4 coefficient has SD
comfortably smaller than its mean.

**Set3 (XGBoost) is the best-performing (set, model) pair on 4survey** (pooled R2 0.281) —
consistent with RQ1's own finding that Set3 tends to edge out Set2/Set4 across this whole
project's model families, not just RQ1's DNN/PINN.

other 6survey cell already showed.

### SHAP values — added 2026-08-11, real-tested against Set4/4survey

New: `models/growth_curve_attribution/compute_rq3_shap.py` + a raw-column sibling of
`compute_shap_values()` (`compute_shap_values_for_columns()` in `xgb_environmental.py`). Unlike
every other number in this note, SHAP is PER-PLOT (one value per plot per feature, not one
number averaged over the whole population) — the only thing in RQ3's current toolkit that can
answer "why is *this specific plot's* prediction what it is," which is what per-plot outlier
diagnosis actually needs, not just "which variable matters on average."

**Refits the 5 per-fold XGBoost models** rather than loading a saved checkpoint —
`run_columns()`'s underlying `run_spatial_cv()` never persisted per-fold XGBoost models to disk
(confirmed by listing the actual output folder: no `xgboost_model.json` there, only the
already-extracted coefficient/importance summaries). Refitting is deterministic given the same
seed, so this reproduces the exact same models already behind this note's coefficient/importance
tables — not a new experiment. Purely local, no cluster time, no new sync needed.
