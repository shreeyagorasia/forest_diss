## What was done

### 1. PINN forward-pass fix -- built, tested, run for real

Background: `models/pinn_env_terrain/pinn_env_terrain.py` and `pinn_env_terrain_k.py`'s
`forward()` never routed the per-plot adjusted $y_{\max}^{(i)}$/$k^{(i)}$ (from the sub-networks)
into the prediction -- only into the physics/trajectory loss terms. This was already documented
as a limitation before this session started.

- Followed `temp_results_pinn/PLAN.md` (pre-existing, detailed isolation plan) closely.
- Built isolated copies with the fix: `temp_results_pinn/pinn_env_terrain_fix/pinn_env_terrain_fix.py`
  ($y_{\max}$-only) and `pinn_env_terrain_k_fix.py` ($y_{\max}$+$k$). `forward()` now returns
  `CR(y_max_i, k_i, age) + trunk_residual` instead of the trunk alone.
- Smoke-tested (`temp_results_pinn/smoke_test/`), then a 40-epoch quicktest
  (`temp_results_pinn/QUICKTEST_RESULTS_2026-08-20.md`), then the **real thing**: full-epoch
  (max_epochs=500, patience=40, matching production), 5-fold `spatial_block_kfold`, 4survey,
  same feature set as the headline table (`nested_set3_gated_terrain_wind_vif`).
- Ran 3 folds locally (Mac, MPS) and 2 folds (3-4) on the university cluster in parallel --
  built cluster infrastructure for this: `temp_results_pinn/pinn_env_terrain_fix/run_cluster_fold.py`
  (CLI runner, one fold/one variant per process) + `temp_results_pinn/jobs/run_pinn_fix_cluster.sh`
  (SLURM script, supports `sbatch --array=0-4`). Results synced back via `rsync` (see
  `reference_icf_cluster_access` memory for the real SSH jump-host details -- no simple alias).
- **Final 5-fold 4survey result** (all output at `temp_results_pinn/outputs/full_rerun/` +
  `full_rerun_cluster/`):

| Variant | Unfixed (original, in dissertation before this session) | Fixed (this session) | DNN (reference) | XGBoost (reference) |
|---|---:|---:|---:|---:|
| PINN ($y_{\max}$-only) | 0.573 | **0.631** | 0.655 | 0.674 |
| PINN-$k$ ($y_{\max}$+$k$) | 0.575 | **0.618** | 0.655 | 0.674 |

  Neither fixed variant beats DNN or XGBoost. No hyperparameter tuning was applied to the fixed
  architecture (unlike DNN's 48-config and XGBoost's 27-config sweeps, already in the chapter).
  6survey was **not** rerun (out of scope, noted everywhere as a limitation).

### 2. Example-plot figure -- what the sub-networks actually learned

- `temp_results_pinn/pinn_env_terrain_fix/run_example_plot_curve.py`: retrains fold 0's fixed
  PINN-$k$, extracts every test-row's predicted $y_{\max}^{(i)}$/$k^{(i)}$, picks one example
  plot, plots its observed trajectory against the population curve and its own learned curve.
- **First selection rule was wrong** -- picked the single largest deviation from the population
  curve, which grabbed a pathological outlier (74-89yo plot, only 4-11m tall, model's own
  adjustment made it worse). Fixed rule (in the script's own comments): exclude implausible
  height-for-age cases, require the fix to actually reduce error, restrict to a moderate
  (interquartile) deviation, then pick the biggest genuine improvement.
- Final example: **plot 119937** (4 observations, ages 53-68), a consistent moderate over-grower
  (~5-6m above population curve at every observation), model's per-plot curve tracks it closely.
  $y_{\max}^{(i)}=52.3$, $k^{(i)}=0.0145$ vs. population $y_{\max}=52.0$, $k=0.0101$.
- Figure code lives in `notebooks/results_figures_q3_rq1.ipynb` (new "Figure R1-3" section,
  reads the saved JSON rather than retraining live -- same convention as that notebook's other
  figures). PNG saved to `figures/fig_results/q3_pinn_example_plot_curve.png`.
- Full per-row test-set predictions also saved: `temp_results_pinn/outputs/example_curve/test_set_predictions.csv`
  (lets a future session pick a *different* example plot without retraining).
