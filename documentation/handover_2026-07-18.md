## What this project is

UoE MSc dissertation: a Physics-Informed Neural Network (PINN) predicting Sitka spruce top-height
growth at Aberfoyle forest, using LiDAR survey data (`4survey`: 71,766 plots, years
2008/2012/2021/2023; `6survey`: 13,897 plots, a subset, years 2002/2006/2008/2012/2021/2023). The
PINN combines a plain neural network with a Chapman-Richards (CR) growth-curve physics constraint.
The dissertation's actual goal is **growth attribution** (explaining *why* plots differ, via
terrain and wind exposure), not a prediction-accuracy competition — see
`documentation/plans_md/Dissertation Plan v5 - 7th June.md`.

Target is raw `elev_percentile_95th` (not the old `Top_Height99`/99th-percentile family, retired
2026-07-28 — see `experiment_log.md`). `yldc` (Yield Class) is kept in the master export for audit
but removed as a model feature everywhere (confirmed via ablation to hurt generalisation in every
model checked).

### 1. Finish the DNN/PINN no-env cluster experiment sequence

Four stages, Stages 1-3 now done (2026-07-30), only Stage 4 left. **Full exact `sbatch` commands
live in `documentation/experiments_to_run.txt` — read that file, don't reconstruct commands from
memory.**

- **Stage 1 (DONE)**: PINN batch-size sweep. **Decision: `batch_size=256` for both cohorts.**
- **Stage 2 (DONE 2026-07-30)**: DNN/PINN base case (`physics_weight=trajectory_weight=1.0`)
  rebuilt against the current pipeline, both cohorts, both splits, fit + evaluated. Confirms DNN
  beats `PINN(w=1.0)` by a real margin in all 4 cohort×split combos (e.g. 4survey spatial_block
  test R²=0.633 vs 0.580) — the "physics constraint hurts at full weight" finding survives the
  full target/`yldc`/batch-size rebuild, not just the retired pipeline.
- **Stage 3 (DONE 2026-07-30)**: PINN physics-weight 10-point grid on `4survey`/`spatial_block`,

  simpler equally-supported weight choice") × both cohorts × all 3 splits (`spatial_block`,
  `temporal`, `temporal_narrow_gap`). Report mean ± SD across seeds, never a single seed. Primary
  reporting cell: `4survey` + `spatial_block`. Exact commands in `experiments_to_run.txt`'s Stage 4

A prior worry worth pre-empting: several early smoke/diagnostic runs finished in under 5 minutes,
which looked like a training failure. It wasn't — checked directly via

### 2. Build `dnn_env_terrain` and `pinn_env_terrain` — currently empty stubs

`models/dnn_env_terrain/` and `models/pinn_env_terrain/` exist only as empty `__init__.py` files.
No model code, no `run_*.py`, no `evaluate_*.py`, no `jobs/` scripts. This is genuinely new work,
not "run the existing pipeline" — building them is the actual point of the environmental-attribution
chain described below.

**What already exists to inform the feature-selection decision** (re-run 2026-07-30 against the
current pipeline, don't redo unless something below changes): `models/xgb_environmental/` (XGBoost
+ SHAP), `models/elasticnet_environmental/` (independent cross-check), and
`models/xgb_environmental/grouped_analysis.py` + `notebooks/environmental_data/
grouped_category_importance.ipynb` (grouped permutation importance + Moran's I before/after, a
second independent cross-check). All three broadly agree that `neighbour_spatial_lag` and
`stand_structure` categories dominate, `soil_site` and `spatial_position_edge_effects` are
negligible — see `experiment_log.md`'s 2026-07-30 entries (TERRAIN_AND_WIND_COLUMNS fix,
neighbour_spatial_lag refit-ablation restoration) for the exact current numbers, and the
2026-07-28/29 entry for the known SHAP-correlation-unreliability caveat (SHAP once ranked
`elevation` top, but ablation showed removing it *improves* held-out R² — this is why three
independent methods are used, not SHAP alone). **These three methods establish association within
a fitted model, not causation** — worth remembering when deciding what "belongs" in Env-PINN's
`y_max(terrain, wind)` sub-network vs. what's just correlated with something that does.

**New this session, not yet folded into that attribution chain**: multi-year HadUK-Grid climate
(`tas_mean`, `groundfrost_mean`, both cohort-specific columns) is integrated and already in the
`climate` category for `xgb_environmental`/`grouped_analysis.py`. Four more HadUK-Grid variables
were identified as downloadable and worth screening but are NOT yet extracted/integrated:
`rainfall`, `tasmax`, `tasmin`, `sun`, `sfcWind` (the script to pull them,
`models/common/download_haduk_multi_year.py`, already supports all of these via its `VARIABLES`
list — extraction into the per-plot table and a `screen_covariate()` pass, matching what
`tas`/`groundfrost` already got, is the remaining step if you want them in the pool before building
Env-PINN). Sentinel-2 vegetation indices (NDMI/NDWI) were also flagged as worth a supplementary
check — agreed in principle, not started; the plan was to add them as a candidate data source and
drop them if they prove similar to existing metrics, same real-evidence screening as everything
else here (**not** narrative-based grouping — see `feedback_check_numbers_not_category.md` in
memory: always re-pull each candidate variable's own numbers, never exclude/include by category
label alone).

## Key findings still believed true (numbers below are from the RETIRED `Top_Height99` pipeline —
## re-verify before citing; the qualitative shape has held up across the rebuild so far)

1. DNN and PINN both beat every baseline under `spatial_block` (primary) and `temporal`
   (secondary) by a real margin.
2. DNN robustly wins `4survey`; DNN and PINN are tied within noise on `6survey` (survived a
   multi-seed reseed check). PINN's established real advantage is training stability, not lower
   error anywhere.
3. The physics constraint hurts at full weight (`pw=tw=1.0`), and that's informative: CR uses one
   global `y_max`, forcing the network to match it as strongly as real data fights the real
   plot-to-plot variation this dissertation exists to explain. This is *why* DNN must stay in the
   comparison at every future stage as the "same features, no physics" control.
4. This connects to Yield Class: Env-PINN's plot-specific `y_max(terrain, wind)` is effectively
   re-deriving Yield Class at finer resolution than Forest Research currently assigns it — the
   sharpest framing for a forestry audience (Worrell 1987 already cited in the dissertation plan
   found Yield Class varies substantially with terrain in Scottish upland sites).
5. Spatial error maps previously showed the same error clusters across all six models (not
   model-specific) — worth re-checking which compartments once Stage 2/3/4 numbers exist on the
   current pipeline, and definitely before finalizing Env-PINN.
6. Why PINN stays justified despite point 2: this dissertation is explicitly not a
   prediction-accuracy competition — it's attribution, which only PINN's physics-anchored
   architecture can provide once `y_max` becomes plot-specific.

## Working conventions worth knowing

- **`documentation/experiment_log.md`**: add one row/entry per experiment config; update in place
  for reruns of the same config, don't duplicate. Timestamps include time-of-day.
- **`documentation/experiments_to_run.txt`**: the live, checkbox-tracked queue of exact cluster
  commands — append to it, don't recreate it, and check items off as they're run. Treat it as more
  current than any command reproduced in this handover file.
- **Cluster sync**: rsync the *whole* `outputs/` and `logs/` directories, not sub-paths.
- **Submitting a batch of cluster jobs**: write the `for`-loop of `sbatch ...` commands to a
  scratch file under `documentation/sbatch_scripts/`, run it on the cluster with
  `bash documentation/sbatch_scripts/<file>.txt`, then delete it — scratch, not a permanent
  artifact.
- **Don't run git commands unless explicitly asked** — the user commits/pushes manually.
- **Code style**: beginner-friendly (W3Schools-tutorial style), not idiomatic/compressed Python.
- **Feature/variable screening**: always re-pull each candidate variable's own real numbers before
  including/excluding it — never group or exclude by narrative/category similarity alone (e.g.
  "both single-snapshot climate sources" was wrong to use as a reason to treat two variables the
  same without checking each one's own numbers).
- **Notebooks**: `.ipynb` files are too large for the `Edit`/`NotebookEdit` tools once they have
  embedded chart output — direct raw-text/JSON manipulation of the file, or a scoped
  temp-notebook-execute-then-splice-by-cell-id workflow, is the reliable fallback. Always
  `ensure_ascii=False` if doing a full `json.dump()`. Re-execute via
  `jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.kernel_name=forest-diss
  <notebook>.ipynb` and confirm zero errors before considering an edit done.
