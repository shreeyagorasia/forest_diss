=====================================================================

CONTEXT: The 2026-07-29 epoch-check found PINN's batch_size=128 isn't just an unfair
comparison vs DNN's 512 -- PINN's best_val_loss never beats its own epoch-1 value at ANY
physics weight tested (1.0, 0.0, 0.05), while DNN converges normally. A 5-epoch local smoke
test at --batch-size 512 already showed PINN improving for the first time. The 512/128 split
itself was never a deliberate "smaller batch helps PINN" finding -- it came from a single
bundled 2026-07-17 tuning pass that changed 4 hyperparameters at once and just happened to
scale both models' batch size by the same 4x factor from different starting points (DNN
128->512, PINN 32->128). So: don't assume 512 is PINN's best size either -- sweep it.

Both run_dnn_noenv.py and run_pinn_noenv.py now take --batch-size (DNN's added 2026-07-30
for symmetry, previously hardcoded). Job scripts updated to match
(jobs/dnn_noenv/run_dnn_noenv.sh, jobs/pinn_noenv/run_pinn_noenv.sh).
