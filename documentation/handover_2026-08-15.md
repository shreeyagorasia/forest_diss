### Working style — carry this over, it's not optional

- **Push back before agreeing.** When I propose a framing, an interpretation, or a way to write
  something up — especially anything that sounds convenient — stress-test it first. Don't validate
  by default.
- **Check real numbers, not category-level assumptions.** If a claim can be verified against a
  TEMP file, the actual code, or a quick recomputation, verify it — don't reason from what "should"
  be true.
- **Never overstate or understate a finding.** Several findings in this project were *corrected*

  one-off.
- Cite specific files, functions, and real numbers. Vague claims aren't useful to me here.

  generate chapter text wholesale unless I explicitly ask for a specific paragraph.

### Live tensions and corrections you need to know about — these are NOT obvious from a fresh read

These are the things most likely to trip up an analysis if you don't know the full story:

1. **RQ1's "winner" is currently unresolved, not settled.** DNN+Set3 was picked as the RQ1 winner
   based on R² (validated via 5-seed reseed, architecture sweep, physics ablation — all real,
   all done). But a *separate* investigation found RQ1's XGBoost baseline had been running on
   unfair, untuned hyperparameters. Refit fairly, XGBoost now **beats DNN on both cohorts**. This
   fix has NOT been adopted into RQ1's production code (only documented as a sensitivity check) —
   I haven't yet decided how to resolve this in the write-up. Don't assume DNN is "the" winner
   without flagging this tension; don't assume XGBoost quietly wins either, without the caveat that
   the fixed config is a hand-picked, unvalidated choice, not a searched optimum.

2. **The "why PINN despite losing to XGBoost on accuracy" argument is real but narrower than first
   hoped.** I checked whether PINN's residual-shrinkage pattern (RQ2a: does environmental
   conditioning help most where the shared curve is worst) was unique to physics-informed models.
   It isn't — XGBoost shows the same qualitative pattern, with comparable-or-larger average
   reduction. The one genuine, evidenced difference is *stability*: DNN's effect is far more
   reproducible fold-to-fold than XGBoost's (5–14x smaller SD). The case for continuing with PINN
   rests on (a) that reproducibility, and (b) structural arguments — PINN's differentiable,
   physically-parametrized `y_max`/`k` output is what makes RQ2a/RQ3's framing possible at all;
   XGBoost cannot produce an equivalent parameter by construction. It does NOT rest on "PINN
   explains the residual more cleanly" — that claim isn't supported and shouldn't appear.

3. **XGBoost hyperparameters were inconsistent across all three RQs, traced and partially fixed:**
   - RQ1 baseline: was raw defaults, bug confirmed, fix exists only as a sensitivity check (not
     adopted).
   - RQ2b: was raw defaults (same bug) — **fixed in production** (`run_rq2_attribution.py`
     edited), all sets refit, SHAP recomputed, headline attribution finding (`CanopyCover`
     dominance) survived the fix intact.
   - RQ3: was never buggy — has used a fixed, hand-picked config since the start. That config's
     origin traces to `explain_signal.py`, a totally different, unvalidated exploratory fit (no
     held-out split at all) — **not the product of any tuning search**, despite how a chapter draft
     paragraph described it ("chosen through preliminary validation"). If you see that claim
     anywhere, it's wrong and needs correcting.
   - A 12-combination grid-search function (`xgb_environmental.py`'s `tune_hyperparameters()`)
     exists in the codebase but is **dead code** — zero call sites anywhere. If a draft or an
     earlier note attributes RQ2's or RQ3's procedure to this grid, that's incorrect.

4. **CanopyCover reverse-causation concern — investigated, not dismissed.** The project's data
   documentation flags `CanopyCover` (RQ2/RQ3's dominant attribution variable) as a possible
   "downstream consequence of growth, not a driver." Checked properly: it's not algebraic leakage
   (unlike `Age`, which genuinely is circular for the CR-residual targets and is excluded
   everywhere), correlation with the targets is moderate (not near-1, ruling out literal
   duplication), but it does share the same ALS flight/pipeline as the height target. A
   baseline-only ablation (stand-structure columns alone, no environment) showed environment adds
   real R² beyond that baseline, and — more decisively — explains real between-compartment
   (spatial) variance that the baseline explains almost none of. Current framing: present
   CanopyCover/thinning as baseline controls, environmental variables' contribution *beyond* that
   baseline as the actual attribution headline. This is a defensible, evidenced position — use it,
   don't re-litigate it from scratch unless new evidence surfaces.

5. **Several earlier findings were self-corrected mid-session after being initially overstated** —
   this is a pattern to watch for, not just historical trivia:
   - GNNWR's "loses on 6survey" was walked back to "underpowered/unstable, no reliable direction"
     after a reseed showed the sign flips across seeds. The 6survey analysis itself is complete
     (3 seeds × 3 sets × 5 folds) — nothing was skipped, only the conclusion changed. 4survey's
     "GNNWR wins" result is unaffected and reliable.
   - RQ3's worst-residual outlier plots were initially assumed to be "disturbance/data-quality
     artifacts" — checked against the project's actual disturbance-classification system and found
     **zero** of them carry any disturbance flag. Revised explanation: likely a yield-class lookup
     mismatch or sub-threshold trajectory instability, not disturbance. If you see the old
     "disturbance artifact" framing anywhere, it's stale.
