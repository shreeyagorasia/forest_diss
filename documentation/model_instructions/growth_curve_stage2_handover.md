## 1. The idea, restated precisely

Instead of comparing every plot against one pooled Chapman-Richards curve (the old, retired
approach), give each plot its **own** growth curve — same fixed shape `(k=p4, p=p5)` as that
plot's own FC-recorded parameters, only `y_max` free per plot — and compare it against the FC's
own **static, per-plot yldc-implied curve** (not the pooled CR fit, and not `GYCspec95`, which is
recomputed per-row from that same row's height+age and is therefore circular with the target).

Comparisons happen in **`Top_Height95` space** (`elev_percentile_95th × 1.1`), matching the FC's
own GYC convention — an explicit user decision, not a default. The modelling target elsewhere in
this project stays `elev_percentile_95th`; only this Stage 2 comparison layer uses
`Top_Height95`.

**Why this is a genuinely different, better-grounded avenue than the old ("Reuben's") approach**,
not just a reframing: the old approach's target (a residual against one pooled curve) was never
validated as a stable, real per-plot quantity before being handed to SHAP/XGBoost for attribution.
This session's temporal stability check (section 3) is a real test the old approach never ran,
and it passed clearly — see the numbers below.

### The p1-p5 caveat (still open, functionally fine to proceed on)

`p1`-`p5` (the FC's own Chapman-Richards-style constants) take **7 distinct value-sets** in this
data, not one universal Sitka-spruce constant as an earlier brainstorm wrongly assumed. Confirmed
directly: constant within a given plot's own rows, but **not** tied to that plot's own `yldc`
(each parameter-set spans the full yldc range). The user's own read: "estimations of average
parameters for Sitka spruce" — plausible, but doesn't explain why 7 sets exist for a
single-species-filtered cohort. **Functionally this doesn't block anything** — each plot's own
recorded tuple is used directly (the only way to stay faithful to how the FC itself computed
`GYCspec95`/`Vol95` for that specific plot) — but the "why 7" question is still genuinely
unresolved and worth a line in the write-up's limitations section. `g1`/`g3` are a *different*,
already-resolved thing: volume-equation coefficients (species+thinning specific, used only in
`Vol95`) — irrelevant to the height/growth-curve work, confirmed via
`documentation/data_exploration_gpkg/Forest LiDAR & Inventory – Key Terms Cheat Sheet.md`.

## 3. Key numbers so far (all reproducible — just re-run the scripts in section 2)

**Temporal stability check** (fit `y_max` from early years only, predict that same plot's own
later held-out years):

| Cohort | Held-out year | Early-fit curve R² | Static yldc curve R² |
|---|---|---|---|
| 4survey | 2021 (9yr ahead) | 0.873 | 0.226 |
| 4survey | 2023 (11yr ahead) | 0.779 | 0.165 |
| 6survey | 2021 (9yr ahead) | 0.525 | 0.101 |
| 6survey | 2023 (11yr ahead) | 0.386 | −0.029 |

Strong, clean validation of the core premise — a plot's own early growth predicts its own future
height far better than its assigned yield class does.

**Disturbance checks** (full-years fit):
- 4survey residual-by-year is smooth and monotonic (−0.36 → −0.19 → −0.03 → +0.45 across
  2008/2012/2021/2023) — reads as shape-misfit, not a disturbance event.
- 6survey shows a real dip specifically at 2021 (−0.57, the single most negative point) — more
  disturbance-like, but the exact survey *month* (not just year) isn't known, so this can't yet
  be checked against a specific storm/drought date.
- Per-plot residual range (max − min residual across a plot's own years): median 2.1m/2.9m, but
  max **47.2m (4survey) / 35.3m (6survey)** — almost certainly data problems (clearfell/replant,
  boundary mismatch), not real growth variance. **Now identified (2026-08-03,
  `models/growth_curve_attribution/long_tail_plots.py`)**: top 2% = 1,137 plots (4survey) / 270
  (6survey). Nearly all share one signature — smooth growth through the first 3 (4survey)/5
  (6survey) surveys, then a 25-32m single-survey collapse (4survey: almost always at 2023;
  6survey: split between 2023 and 2002) — not explained by recorded `Thin`/`last_thinn`, and
  clustered heavily by compartment (4survey's worst compartment, `2033`, alone holds 142 of the
  1,137 flagged plots). Reads as clearfell/replant or storm/windthrow at the compartment level,
  not scattered per-plot noise — see `documentation/experiment_log.md`'s 2026-08-03 entry for the
  full reasoning. Not yet resolved which of the two (management felling vs. weather event) it is,
  or whether to drop just the corrupted survey-year vs. the whole plot.
- Thinning-during-gap plots show bias consistently closer to zero than non-thinned plots, in
  *both* cohorts (even though the cohorts' overall bias sign disagrees) — consistent with the
  forestry fact that top height is relatively thinning-invariant by design (thinning removes
  suppressed/intermediate trees, not the dominants that define top height) — thinning normalises
  growth toward the textbook curve rather than boosting past it.

**Phase 0 checks:**
- Every plot has exactly 4 (4survey) or 6 (6survey) distinct survey years — a genuinely balanced
  panel, no low-timestamp subgroup to worry about.
- yldc deviation has real, non-degenerate spread (mean +1.58m/+2.19m, std 6.5m/4.7m) that *grows*
  with Age (contradicts an initial low-Age-instability guess — corrected once checked).
- 96.3% (4survey) / 97.1% (6survey) of `spatial_block_split` test plots have **zero** train-plot
  neighbours within 75m (mean distance to nearest train plot ~260-295m) — the same structural
  problem already found fatal for the leak-safe `neighbour_mean_height` feature in Stage 1,
  confirmed here to very likely recur for any short-bandwidth spatial mechanism (GNNWR/GRF).

## 4. Candidate architectures (shortlisted, not chosen — user chose to keep 2-3 open rather than commit)

Important distinction the user corrected once already: **NLME/GADA is not a candidate AI
model** — it's the cheap statistical feasibility diagnostic (does per-plot `y_max` even work at
all), which section 3 already substantially answered. `models/spatial_attribution/nlme.py` is a
*different* thing from this Stage 2 work (compartment-grouped linear mixed model on
`mean_cr_residual`, not a per-plot curve) — don't conflate the two.

The actual shortlist (details/tradeoffs discussed at length in the conversation this handover
comes from, not fully repeated here):
1. **Per-plot fixed-shape curve fit** (the closed-form fit already built in section 2) + XGBoost
   attribution of the deviation via terrain/wind — cheapest, reuses `xgb_environmental.py`/
   `elasticnet_environmental.py` unchanged with a new `target_col`.
2. **Bayesian hierarchical nonlinear growth model** (PyMC) — partial pooling of `y_max` across
   plots/compartments, terrain/wind on the group-level mean, full posterior uncertainty.
3. **GNNWR-style hypernetwork, or its tree-based relatives** (GRF, Mixed-Effects Random
   Forest/GPBoost) — explicitly **not** a PINN: no physics-loss term, plain MSE against a target,
   CR shape applied only as post-hoc conversion. GPBoost/MERF specifically answers two things
   already proven in this project: linear NLME is inadequate (only ~5% compartment variance
   explained) and trees beat a plain MLP at extracting this exact small terrain signal — worth
   weighing above GNNWR precisely because GNNWR's local mechanism is neural.

Any of these needs problem 5 (neighbour coverage) resolved first if it involves a distance-based
mechanism — likely means a large bandwidth (hundreds-to-thousands of metres, closer to the
~3,956m semivariogram range already measured for the CR residual in Stage 1), not a short local
radius.

## 5. The 6 problems to investigate deeply now (this is the actual next work)

Ranked roughly by how cheap/foundational they are — resolve 1-3 before spending real effort on
4-6, since 1-3 use data already on disk and could change what 4-6 even mean.

1. **4survey shape-misfit.** The fixed `(k,p)` per plot may not flex enough even with `y_max`
   free. Investigate: per-plot fit-quality distribution (residual std within each plot's own
   fitting), whether misfit correlates with anything (Age at first survey, yldc value, region) —
   and consider whether the smooth monotonic pattern itself has a mechanical explanation (e.g. how
   least-squares balances error across unevenly-spaced points) before assuming it's ecological.
2. **Long-tail data-quality plots (up to 47m swing).** Identified 2026-08-03 (see experiment
   log) — 1,137/270 plots (4survey/6survey), overwhelmingly a single-survey height collapse
   clustered by compartment. Still open: management felling vs. storm/windthrow (changes whether
   this is pure data-quality exclusion or a genuine, environment-attributable disturbance
   signal), and whether to drop the one corrupted plot-year or the whole plot. Also now a
   **blocking dependency for the compartment-variance ICC check** below (0.399/0.188 measured on
   the full population, not yet re-checked with these plots resolved).
3. **4survey vs. 6survey disagreement** (bias direction flips sign between cohorts). 6survey's
   plots are a subset of 4survey's own broader plot population (per this project's established
   convention) — check the overlap directly, and if it exists, compare the *same physical plots'*
   behaviour under each cohort's own fitting window, to tell a real cohort effect apart from a
   plot-selection artefact.
4. **Terrain/wind's established ceiling (R²≈0.16-0.19 everywhere else in this project).** Only
   answerable by actually building the attribution step once 1-3 are resolved — reuse
   `xgb_environmental.py` with the new deviation as `target_col`.
5. **Neighbour-coverage blocking short-bandwidth spatial mechanisms.** Decide bandwidth strategy
   (large bandwidth vs. Candidate A/tabular-only) before building any of Candidates 2-3 above.
6. **The unmeasured 2012→2021 gap.** Still a fundamental blind spot. The external
   disturbance-timeline idea (extending `download_haduk_multi_year.py` to every calendar year, UK
   Met Office named-storm archive) is real and buildable but deliberately deprioritised behind
   1-3, which are cheaper and use only data already in hand.
7. **Compartment-pooling variance check (added 2026-08-03).** ICC of `yldc_deviation` by `cpmt`:
   0.399 (4survey) / 0.188 (6survey) — a real, substantial signal, genuinely different from the
   ~5% figure the NLME/`mean_cr_residual` check found for a different target, confirming that
   number doesn't transfer. Directly gates whether Candidate B (Bayesian hierarchical partial
   pooling across compartments) is worth building — but the number is measured on the full
   population including problem 2's long-tail plots, which cluster by compartment themselves, so
   it must be re-run once problem 2 is resolved before trusting it as a clean "pooling would
   help" signal.
